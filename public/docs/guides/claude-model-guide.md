## 3つのモデルの特徴

Claude には用途に応じた3つのモデルがあります。タスクの複雑さに合わせて使い分けることで、コストを抑えながら品質を維持できます。

| モデル | コスト | 向いているタスク |
|---|---|---|
| Claude Opus 4.7 | 高 | 複雑な設計・セキュリティレビュー・アーキテクチャ判断 |
| Claude Sonnet 4.6 | 中 | 日常的なコーディング・バグ修正・PR作成 |
| Claude Haiku 4.5 | 低 | 単純な変換・フォーマット・自動化パイプライン |

---

## Claude Opus 4.7 — 重要な判断を任せる

**使う場面**: 1回あたり時間をかける大きなタスク

Opus は推論力が最も高く、複雑なコンテキストを正確に理解します。ただしコストが高いため、毎回のコーディングには使いません。

**適切な用途:**
- システム全体のアーキテクチャを見直す
- セキュリティ上のリスクをレビューする
- 大規模なリファクタリングの方針を立てる
- 複数ファイルにまたがる設計判断

**プロンプト例:**
```
このシステム全体のアーキテクチャを見直して。
特に認証フローとデータの流れに問題がないか確認して。
改善案があれば優先度順に提案して。
```

---

## Claude Sonnet 4.6 — 日常のメイン

**使う場面**: コーディングセッションのほとんどのタスク

Sonnet はコストと品質のバランスが最も良く、ほとんどの開発タスクはこれで十分です。Claude Code のデフォルトとして使うのに最適です。

**適切な用途:**
- 機能の実装・バグ修正
- テストコードの生成
- PR の説明文・コミットメッセージの作成
- コードの説明・ドキュメント生成

**プロンプト例:**
```
この関数のバグを修正して。
修正前に影響範囲を grep して確認してから変更して。
```

---

## Claude Haiku 4.5 — 大量の軽作業に

**使う場面**: 定型処理・自動化パイプライン

Haiku はコストが最も低く、高速です。単純な変換や大量の繰り返し処理に向いています。

**適切な用途:**
- 変数名・関数名のリネーム
- ファイルフォーマットの一括変換
- 短い質問への回答
- 自動化パイプラインの各ステップ

**プロンプト例:**
```
この関数名をすべてスネークケースに変えて。
他のロジックは変更しないこと。
```

## モデルを切り替える方法

Claude Code では `/model` コマンドでセッション中にモデルを変更できます。

```bash
# Opusに切り替え（重要な設計判断のとき）
/model claude-opus-4-7

# Sonnetに戻す（通常のコーディング）
/model claude-sonnet-4-6

# Haikuに切り替え（大量の軽作業）
/model claude-haiku-4-5-20251001
```

## 使い分けのフロー

```
タスクを受け取る
  ↓
複雑な設計判断・セキュリティレビューか？
  → YES → Opus 4.7
  → NO  ↓
単純な変換・定型処理か？
  → YES → Haiku 4.5
  → NO  → Sonnet 4.6（デフォルト）
```
