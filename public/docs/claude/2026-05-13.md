## 🆕 今週の注目トピック

### Claude 4 モデルファミリーの全体像

Claude 4 世代は Opus 4.7 / Sonnet 4.6 / Haiku 4.5 の3モデル体制。それぞれ用途が明確に分かれており、使い分けがコストと品質を大きく左右する。

- **Opus 4.7** — 最高品質。複雑なアーキテクチャ設計・大規模リファクタリング・セキュリティ監査に最適
- **Sonnet 4.6** — バランス型。日常的なコーディング・PR レビュー・ドキュメント生成の主力
- **Haiku 4.5** — 高速・低コスト。定型処理・データ変換・繰り返しタスクの自動化に

### Claude Code の現在地

Claude Code は単なる補完ツールではなく「エージェント型 CLI」として進化している。特に注目すべき点：

- **サブエージェント並列実行** — 複数のタスクを独立したエージェントで同時処理
- **MCP（Model Context Protocol）** — 外部ツール・DB・API との接続を標準化
- **Hooks システム** — ツール実行前後にカスタムスクリプトを差し込める
- **CLAUDE.md** — プロジェクトごとのルール・コンテキストを永続化

## ⚡ 開発効率を上げる実践Tips

### 1. CLAUDE.md を「仕様書」として使う

単なる説明文ではなく、生成物のフォーマットを厳密に定義することで出力の一貫性が上がる。

```markdown
# このプロジェクトのルール

## コーディング規約
- TypeScript strict モード必須
- コンポーネントは named export のみ
- CSS は Tailwind CSS v4 のみ使用

## 禁止事項
- `any` 型の使用
- `console.log` のコミット
- デフォルト export（index.ts 除く）

## ファイル命名
- コンポーネント: PascalCase.tsx
- ユーティリティ: camelCase.ts
- 定数: SCREAMING_SNAKE_CASE
```

### 2. サブエージェントで並列調査

リサーチ系タスクは並列化で大幅に時間短縮できる。

```
「以下を並列で調査してください：
1. Prisma vs Drizzle の比較（パフォーマンス観点）
2. Neon vs PlanetScale の比較（コスト観点）
3. 現在の package.json の依存関係の脆弱性チェック」
```

3つのサブエージェントが同時に動き、結果をまとめて返してくる。逐次実行より 3〜5 倍速い。

### 3. /compact でコンテキストを節約

長いセッションでは `/compact` を打つとコンテキストを要約・圧縮してくれる。トークン上限に近づく前に使うのが鉄則。

目安：レスポンスが遅くなり始めたら `/compact` のサイン。

### 4. Think ツールで複雑な設計を解決

難しい設計判断をする前に明示的に考えさせる。

```
「新しい認証システムを設計する前に、
現在のコードベースの認証フローを隅々まで理解してください。
特に session 管理・middleware・型定義の関係を整理してから
設計案を出してください」
```

「考えてから答える」を明示すると精度が上がる。

### 5. エラーメッセージをそのまま貼る

```
「以下のエラーが出ています。原因と修正方法を教えてください：

TypeError: Cannot read properties of undefined (reading 'map')
  at DigestContent (components/DigestContent.tsx:45:23)
  at ...」
```

スタックトレースを整形せずにそのまま貼るのがベスト。Claude は文脈から原因を特定できる。

### 6. 「なぜ」を伝えるとより良い提案が出る

```
// ❌ 曖昧
「このコードをリファクタリングしてください」

// ✅ 意図明確
「このコードは今後 5 人のチームで開発する予定です。
可読性と型安全性を重視してリファクタリングしてください。
パフォーマンスより保守性を優先します」
```

## 🛠 個人開発者向け おすすめワークフロー

### 新機能の開発フロー（Claude Code 活用版）

```
1. 仕様を自然言語で書く
   「ユーザーがメールアドレスとパスワードでログインできる機能を追加したい」

2. Claude に設計を相談する
   「この機能を実装する前に、現在の認証周りのコードを読んで
    最適な実装方針を3つ提案してください」

3. 一番シンプルな案を選んで実装させる
   「方針2で進めます。まず型定義とAPIルートから作ってください」

4. レビューと修正
   「実装できました。セキュリティ上の問題がないか確認してください」

5. テスト作成
   「この実装に対してユニットテストを書いてください」
```

### バグ調査フロー

```
1. 症状を正確に伝える
   「ログインページで正しいパスワードを入力しても
    401 エラーが返る。本番環境のみで発生、ローカルは正常」

2. 関連ファイルを特定させる
   「このバグに関係しそうなファイルをリストアップしてください」

3. 仮説を立てさせる
   「考えられる原因を優先度順に並べてください」

4. 絞り込んで修正
   「仮説1を検証・修正してください」
```

### コスト最適化フロー

```bash
# 安いモデルでドラフトを作り、高いモデルでレビューする
$ claude --model haiku "このAPIのレスポンス型を定義してください"
# → 型のドラフト生成

$ claude --model opus "この型定義に漏れや問題がないかレビューしてください"
# → 精査
```

## 💡 モデル使い分けガイド（週1回更新）

| モデル | 主な用途 | 向かないケース | コスト感 |
|--------|----------|---------------|---------|
| Opus 4.7 | 複雑な設計・セキュリティ監査・難解なバグ調査 | 定型作業・高頻度タスク | 高（慎重に使う） |
| Sonnet 4.6 | 日常コーディング・PR レビュー・ドキュメント | 超単純なタスク | 中（メインモデル） |
| Haiku 4.5 | データ変換・定型処理・大量バッチ | 複雑な判断が必要なもの | 低（気軽に使える） |

### 判断フロー

```
このタスクは複雑？
├── Yes → 設計が絡む？
│         ├── Yes → Opus 4.7
│         └── No  → Sonnet 4.6
└── No  → 繰り返し or 大量？
          ├── Yes → Haiku 4.5
          └── No  → Sonnet 4.6
```

### コスト感の目安（個人開発レベル）

- **月 $5 以内に抑えたい** → Haiku メイン、Sonnet はレビューのみ
- **月 $20 程度** → Sonnet メイン、Opus は週 1〜2 回の設計判断のみ
- **制限なし** → Sonnet メイン、複雑なときだけ Opus
