## 🆕 今週の注目トピック

### Claude Code Hooks とは

Hooks は、Claude Code がツールを使う「前後」にシェルコマンドを自動実行できる仕組み。Claude の動作に自分のスクリプトを割り込ませることができる。

**使える Hook の種類:**

| Hook | タイミング | 用途 |
|------|-----------|------|
| `PreToolUse` | ツール実行の直前 | バリデーション・ログ・確認 |
| `PostToolUse` | ツール実行の直後 | lint・テスト自動実行 |
| `Stop` | Claude の応答が終了したとき | 通知・サマリー生成 |
| `Notification` | Claude が通知を送るとき | Slack 通知・デスクトップ通知 |

設定は `~/.claude/settings.json`（グローバル）または `.claude/settings.json`（プロジェクト）に書く。

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [
          {
            "type": "command",
            "command": "pnpm lint --fix"
          }
        ]
      }
    ]
  }
}
```

## ⚡ 開発効率を上げる実践 Tips

### 1. ファイル編集後に自動で lint を走らせる

Claude が `Edit` または `Write` でファイルを変更するたびに ESLint を自動実行する。手動で lint を忘れるミスがなくなる。

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "pnpm lint --fix --quiet 2>&1 | tail -5"
          }
        ]
      }
    ]
  }
}
```

`matcher` は正規表現で複数ツールを指定できる。`tail -5` で出力を最後の5行に絞るとノイズが減る。

### 2. TypeScript の型エラーを即座に検出する

ファイル保存のたびに型チェックを走らせて、型エラーを早期に検出する。

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "pnpm tsc --noEmit 2>&1 | grep 'error TS' | head -10"
          }
        ]
      }
    ]
  }
}
```

出力を `grep 'error TS'` で型エラーのみに絞ることで、Claude が出力を参照して次の編集で修正できる。

### 3. Bash 実行前に危険なコマンドをブロックする

`PreToolUse` で Bash コマンドの内容をチェックして、危険な操作を防ぐ。

```bash
#!/bin/bash
# scripts/bash-guard.sh
# stdin から Bash ツールの入力 JSON を受け取る
INPUT=$(cat)
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command // ""')

# 危険なパターンを検出
if echo "$COMMAND" | grep -qE '(rm -rf|drop table|DELETE FROM.*WHERE 1|force-push)'; then
  echo "⛔ ブロック: 危険なコマンドが検出されました: $COMMAND" >&2
  exit 1  # 0以外を返すとツール実行がキャンセルされる
fi

exit 0
```

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "bash scripts/bash-guard.sh"
          }
        ]
      }
    ]
  }
}
```

**Hook の終了コード:**
- `0` → ツール実行を許可
- `0以外` → ツール実行をキャンセル（PreToolUse のみ）

### 4. 作業ログを自動で記録する

Claude が何をしたか `.claude-log.md` に自動記録する。「あの変更いつやったっけ？」が解決する。

```bash
#!/bin/bash
# scripts/log-tool.sh
TOOL=$1
TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
INPUT=$(cat)

# ファイルパスを抽出（Edit/Write の場合）
FILEPATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // .tool_input.command // ""' 2>/dev/null)

echo "- [$TIMESTAMP] $TOOL: $FILEPATH" >> .claude-log.md
```

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": ".*",
        "hooks": [
          {
            "type": "command",
            "command": "bash scripts/log-tool.sh \"$CLAUDE_TOOL_NAME\""
          }
        ]
      }
    ]
  }
}
```

### 5. 作業完了時に macOS 通知を送る

長い処理が終わったときに `Stop` Hook でデスクトップ通知を出す。別の作業をしながら待てる。

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude Code の処理が完了しました\" with title \"DevKnow\"'"
          }
        ]
      }
    ]
  }
}
```

Linux の場合は `notify-send`、Windows は `powershell` のトースト通知が使える。

### 6. テスト対象ファイルが変更されたら自動でテストを実行する

`__tests__/` 配下のファイルが変更されたときだけ Vitest を走らせる。

```bash
#!/bin/bash
# 変更されたファイルパスを stdin から取得
INPUT=$(cat)
FILEPATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // ""')

# テストファイルまたはテスト対象のファイルが変更された場合のみ実行
if echo "$FILEPATH" | grep -qE '(__tests__|\.test\.|\.spec\.)'; then
  echo "🧪 テスト実行: $FILEPATH"
  pnpm vitest run "$FILEPATH" 2>&1 | tail -20
fi
```

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "bash scripts/auto-test.sh"
          }
        ]
      }
    ]
  }
}
```

## 🛠 今日試すべきワークフロー

### プロジェクトに Hook を設定する（10分）

**ステップ 1: `.claude/settings.json` を作成**

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "pnpm tsc --noEmit 2>&1 | grep 'error TS' | head -5"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"完了\" with title \"Claude Code\"' 2>/dev/null || true"
          }
        ]
      }
    ]
  }
}
```

**ステップ 2: Claude Code を再起動して Hook を有効化**

設定ファイルを変更したあとは Claude Code を再起動する。`/hooks` コマンドで現在の Hook 設定を確認できる。

**ステップ 3: 動作確認**

```
「tsconfig.json を読んで、問題があれば指摘して」
```

Edit ツールが走るたびに型チェックが自動実行される。型エラーが出れば Claude がその場で修正できる。

### Hook スクリプトのデバッグ方法

Hook コマンドの出力は Claude の会話に表示されるので、`echo` で確認できる。

```bash
# Hook が動いているか確認
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{ "type": "command", "command": "echo '[Hook] Edit 検知: ファイルが変更されました'" }]
      }
    ]
  }
}
```

Hook の中で重い処理を走らせると Claude の応答が遅くなる。`&` をつけてバックグラウンド実行にすると応答速度を維持できる。

```bash
# バックグラウンドで実行（応答を待たない）
"command": "pnpm test &"
```

## 💡 モデル使い分けガイド（週1回更新）

| モデル | 主な用途 | 向かないケース | コスト感 |
|--------|----------|---------------|---------|
| Opus 4.7 | エージェント設計・複雑な推論・セキュリティ監査 | 定型作業・高頻度バッチ | 高 |
| Sonnet 4.6 | API 組み込み・日常コーディング・Hook スクリプト開発 | 超単純な変換処理 | 中（メイン） |
| Haiku 4.5 | バッチ処理・大量ドキュメント変換・分類タスク | 複雑な推論が必要なもの | 低 |

### Hook 開発でのモデル選択

| タスク | 推奨モデル | 理由 |
|--------|-----------|------|
| Hook スクリプトの設計 | Sonnet 4.6 | シェルスクリプト + JSON 設定の整合が必要 |
| jq/bash での JSON 処理 | Sonnet 4.6 | ツール入力の解析に推論が必要 |
| 単純な通知コマンド | Haiku 4.5 | osascript / notify-send のパターンは定型 |
| セキュリティガードの設計 | Opus 4.7 | 抜け漏れを防ぐために丁寧な推論が必要 |

### 今週のコスト最適化ポイント

Hook で型チェックや lint を自動化すると、Claude が「エラーを見てから修正」のループを自分で回せる。その分「手動で確認してから次を依頼する」往復が減り、トータルのトークン消費が下がる。

## 📌 今日の一言

> Hook の真価は「Claude を監視する」のではなく「Claude と連携する」こと。
> lint エラーを Hook で渡すと、Claude は次の編集で自動的にそれを修正する。
> 人間が確認→指摘→修正の仲介役になる必要がなくなる。
