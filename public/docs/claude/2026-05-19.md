## 🆕 今週の注目トピック

### MCP（Model Context Protocol）とは

MCP は Claude Code が外部サービス・ツールのデータを直接参照するための標準プロトコル。GitHub・Notion・Slack などとの連携が、専用 API インテグレーションを書かずに実現できる。

**何が変わるか:**
- Claude がリポジトリの Issue・PR を直接読んで実装できる
- Notion のドキュメントを参照しながらコードを書ける
- Slack のスレッドを要約しながらタスクを進められる

MCP サーバーは Node.js または Python のローカルプロセスで、stdio または HTTP で Claude と通信する。

**使える MCP サーバーの種類:**

| サーバー | 提供元 | 主な用途 |
|---------|--------|---------|
| `@modelcontextprotocol/server-github` | Anthropic 公式 | Issue・PR・コードの読み書き |
| `@modelcontextprotocol/server-filesystem` | Anthropic 公式 | プロジェクト外ファイルの参照 |
| `@modelcontextprotocol/server-postgres` | Anthropic 公式 | DB の直接クエリ |
| `@modelcontextprotocol/server-slack` | Anthropic 公式 | チャンネル・スレッドの参照 |
| カスタム | 自作 | 社内 API・独自ツールの接続 |

## ⚡ 開発効率を上げる実践 Tips

### 1. MCP サーバーを `.claude/settings.json` に追加する

MCP サーバーはプロジェクトの `.claude/settings.json`（プロジェクト限定）またはグローバルの `~/.claude/settings.json` に登録する。

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_xxxxx"
      }
    }
  }
}
```

登録後に Claude Code を再起動すると `/mcp` コマンドで接続状態を確認できる。

### 2. GitHub MCP で Issue から実装まで一気通貫

GitHub MCP サーバーを使うと、自然言語で Issue の読み込み・実装・PR 作成が連続してできる。

**使用例:**

```
「リポジトリ owner/repo の open な Issue を確認して、
 優先度が高そうなものを 1 件選んで実装してください。
 実装後に PR を作成してください。」
```

```
「PR #42 のレビューコメントを全部読んで、
 まだ対応していないコメントをリストアップして修正してください。」
```

MCP なし（従来のフロー）:
1. ブラウザで GitHub を開く → Issue を読む → 内容をコピー → Claude に貼り付け → 実装 → PR 文を書く

MCP あり:
1. 「Issue #15 を読んで実装して PR を作って」だけ

コンテキスト切り替えが消えるのが最大の恩恵。

### 3. Filesystem MCP でプロジェクト外のファイルを参照する

別リポジトリの仕様書・設計書を Claude に読ませたいときは Filesystem MCP が使える。

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y", "@modelcontextprotocol/server-filesystem",
        "/Users/yourname/Documents/specs",
        "/Users/yourname/projects/shared-libs"
      ]
    }
  }
}
```

**使用例:**
```
「~/Documents/specs/auth-spec.md を読んで、
 それをもとに lib/auth.ts を実装してください。」
```

許可するディレクトリだけ引数に渡すことでアクセス範囲を限定できる。

### 4. PostgreSQL MCP で DB を直接クエリする

Neon や SupabaseなどのPostgreSQL を Claude に直接クエリさせる。

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": [
        "-y", "@modelcontextprotocol/server-postgres",
        "postgresql://user:pass@host/dbname"
      ]
    }
  }
}
```

**使用例:**
```
「users テーブルのスキーマを確認して、
 最近 30 日間登録したユーザーのうち一度もログインしていない人数を教えてください。」
```

本番 DB への接続は読み取り専用ユーザーを使うことを強く推奨。

### 5. カスタム MCP サーバーを自作する

社内ツールや独自 API を Claude に接続したい場合は MCP サーバーを自作する。

```bash
npm install @modelcontextprotocol/sdk
```

```typescript
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";

const server = new Server(
  { name: "internal-tickets", version: "1.0.0" },
  { capabilities: { tools: {} } }
);

server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: "get_ticket",
      description: "社内チケット管理からチケット情報を取得する",
      inputSchema: {
        type: "object",
        properties: {
          ticket_id: { type: "string", description: "チケット ID（例: TKT-123）" },
        },
        required: ["ticket_id"],
      },
    },
  ],
}));

server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === "get_ticket") {
    const { ticket_id } = request.params.arguments as { ticket_id: string };
    const ticket = await fetchFromInternalAPI(ticket_id);
    return {
      content: [{ type: "text", text: JSON.stringify(ticket, null, 2) }],
    };
  }
  throw new Error(`Unknown tool: ${request.params.name}`);
});

const transport = new StdioServerTransport();
await server.connect(transport);
```

`.claude/settings.json` に登録:
```json
{
  "mcpServers": {
    "internal-tickets": {
      "command": "node",
      "args": ["./mcp-servers/tickets.js"]
    }
  }
}
```

### 6. MCP サーバーのデバッグ方法

MCP の接続エラーは `/mcp` コマンドで確認できる。サーバーが起動しない場合はコマンドを手動で実行してエラーを確認する。

```bash
# GitHub MCP を手動起動してエラーを見る
GITHUB_PERSONAL_ACCESS_TOKEN=ghp_xxx npx -y @modelcontextprotocol/server-github
```

`Listening on stdio...` のようなメッセージが表示されれば起動成功。`command not found` や認証エラーが出た場合はトークン・パッケージ名を確認する。

## 🛠 今日試すべきワークフロー

### GitHub MCP を使った Issue ドリブン開発（15分）

**ステップ 1: GitHub Personal Access Token を発行**

GitHub の Settings → Developer settings → Personal access tokens で `repo` スコープのトークンを作成。

**ステップ 2: `.claude/settings.json` に追加**

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_your_token_here"
      }
    }
  }
}
```

**ステップ 3: Claude Code を再起動して `/mcp` で確認**

```
/mcp
```

`github: connected` と表示されれば準備完了。

**ステップ 4: Issue から実装を流す**

```
「open な Issue を全部一覧表示して、難易度が低くて重要なものを
 1 件選んで実装してください。実装後に PR を作成してください。」
```

**ステップ 5: PR レビューの自動対応**

```
「PR #XX の未解決レビューコメントをすべて読んで対応してください。」
```

## 💡 モデル使い分けガイド（週1回更新）

| モデル | 主な用途 | 向かないケース | コスト感 |
|--------|----------|---------------|---------|
| Opus 4.7 | MCP サーバー自作・複雑なエージェント設計・セキュリティ設計 | 定型作業・高頻度バッチ | 高 |
| Sonnet 4.6 | GitHub MCP 連携・日常コーディング・PR 作成 | 単純な分類・変換 | 中（メイン） |
| Haiku 4.5 | Issue の大量分類・ラベル付け・単純な変換 | 複雑な推論が必要なもの | 低 |

### MCP 活用でのモデル選択

| タスク | 推奨モデル | 理由 |
|--------|-----------|------|
| MCP サーバーの自作 | Opus 4.7 | SDK の型整合と設計に推論が必要 |
| Issue からの実装 + PR 作成 | Sonnet 4.6 | コード実装と文書作成の複合タスク |
| Issue の分類・タグ付け | Haiku 4.5 | テキスト分類は定型処理 |
| DB クエリの解釈と最適化 | Sonnet 4.6 | スキーマ理解 + SQL 生成の整合が必要 |

## 📌 今日の一言

> MCP の本質は「Claude の外側にある情報を Claude の内側に持ち込む」こと。
> Issue 管理・ドキュメント・DB を接続した瞬間、
> Claude は「コードを書くツール」から「開発全体を回すエージェント」に変わる。
