## 🆕 今週の注目トピック

### CLAUDE.md は「Claude への指示書」

CLAUDE.md はリポジトリのルートに置くことで、全セッションで自動的に読み込まれるプロジェクト固有の指示書。「このプロジェクトではこういうルールで動いてほしい」を一度書けば、毎セッションで繰り返す必要がなくなる。

**CLAUDE.md の読み込み優先順位:**

| ファイル | 適用範囲 |
|---------|---------|
| `~/.claude/CLAUDE.md` | ユーザーグローバル（全プロジェクト共通） |
| `CLAUDE.md` | プロジェクトルート全体 |
| `components/CLAUDE.md` | components/ 以下の作業時のみ追加適用 |

サブディレクトリの CLAUDE.md はネストして使える。「このコンポーネントはこの設計原則に従う」という粒度でルールを分けられる。

### @インポートで CLAUDE.md を分割できる

CLAUDE.md が長くなったら `@ファイルパス` で別ファイルを参照できる。

```markdown
# CLAUDE.md

@AGENTS.md
@docs/coding-standards.md
@docs/api-conventions.md
```

チームで管理するときは規約ごとにファイルを分けると更新が楽になる。

## ⚡ 開発効率を上げる実践 Tips

### 1. CLAUDE.md に書くべき 7 つの項目

```markdown
# プロジェクト名

## 禁止事項（最優先）
- .env は絶対に読み書きしない
- prisma/migrations/ は変更しない（マイグレーションは手動）
- console.log を本番コードに残さない
- Stripe は new Stripe() をトップレベルに書かない（ビルド時クラッシュのため）

## コード規約
- TypeScript: strict モード、any 型禁止
- コメントは書かない（コードで意図を表現する）
- 関数は 20 行以内（超える場合は分割を提案する）

## 技術スタック
- フレームワーク: Next.js 16 App Router
- DB: Neon Serverless PostgreSQL
- 認証: iron-session v8（cookie 名: myapp-auth）
- スタイル: Tailwind CSS v4（CSS 変数でテーマ管理）

## ディレクトリ構造
- app/(app)/ — 認証必須ページ
- app/(landing)/ — ランディングページ
- lib/ — サーバーサイドのユーティリティ
- components/ — React コンポーネント

## テスト方針
- 外部 API 呼び出しはモックしない（実 DB を使う）
- テストファイルは __tests__/ に置く

## よく使うコマンド
- 開発: npm run dev
- 型チェック: npx tsc --noEmit

## 注意事項
- ページは Server Component デフォルト
- クライアントコンポーネントには 'use client' が必要
```

### 2. 「なぜ」を書くとエッジケースで Claude が自分で判断できる

理由なしのルールはエッジケースで判断できない。

```markdown
# 悪い例
- Stripe はモジュールトップに書かない

# 良い例
- Stripe はトップレベルで初期化しない。ビルド時に STRIPE_SECRET_KEY が
  存在しないとクラッシュするため。必ず getStripe() の遅延初期化パターンを使う。
```

「この場合は例外でいいか？」の判断を Claude が自分でできるようになる。

### 3. サブエージェントで独立タスクを並列処理する

Claude Code の `Agent` ツールを使うと独立したサブタスクを並列で実行できる。

**並列処理の効果が出るケース:**
- 複数ファイルの独立したリファクタリング
- テストの生成と実装の調査を同時に
- 複数ページの SEO メタデータを一括で更新

**使い方:**
```
「以下を並列で実行してください:
1. components/Button.tsx のアクセシビリティを改善する
2. lib/auth.ts にユニットテストを追加する
3. app/(landing)/page.tsx のパフォーマンスボトルネックを分析する」
```

Claude は 3 つのサブエージェントを立ち上げて並列で処理する。直列の場合と比べて完了時間が大幅に短縮できる。

**注意:** 同じファイルを複数エージェントが同時に編集しようとすると競合する。編集対象が重なるタスクは直列で実行させる。

### 4. /compact でコンテキストを整理してから次のフェーズへ

`/compact` は会話の要約を生成して、コンテキストウィンドウを解放する。

**実行タイミングの目安:**
- 大きな実装が一段落したとき
- 応答速度が遅くなってきたと感じたとき
- 「設計フェーズ → 実装フェーズ」など作業の性質が変わるとき

要約内容は会話に表示されるので内容を確認してから次に進める。

### 5. TodoWrite でタスクを可視化して脱線を防ぐ

複数ステップの作業はタスクリストを渡すと「いまどこにいるか」が明確になり、長いセッションでも迷走しにくくなる。

```
「以下のタスクリストを管理しながら実装してください:
1. ユーザー登録 API の作成
2. メール認証フローの実装
3. セッション管理の追加
4. フロントエンドのフォームと連携

1 つ完了するたびに done にマークして次に進んでください。」
```

途中で中断しても再開しやすく、「どこまで実装したか」の確認コストが下がる。

### 6. コンポーネントディレクトリに CLAUDE.md を追加する

規模が大きくなってきたら `components/CLAUDE.md` を追加してコンポーネント設計ルールを局所化する。

```markdown
# components/CLAUDE.md

## このディレクトリのコンポーネント設計原則

- Server Component をデフォルトにする
- 'use client' はインタラクティブな部分だけに限定する
- Props はすべて型定義する（type ではなく interface を使う）
- コンポーネントファイルは 1 ファイル 1 コンポーネント

## スタイリングルール
- Tailwind のインラインクラス + CSS 変数（var(--text) など）で色を管理する
- ハードコードのカラーコードは使わない
- レスポンシブは mobile-first（sm: md: lg: の順）

## 禁止パターン
- nested button（button の中に button を入れない）
- onClick を Server Component に付ける
- dangerouslySetInnerHTML の使用
```

## 💡 モデル使い分けガイド（週1回更新）

| モデル | 主な用途 | 向かないケース | コスト感 |
|--------|----------|---------------|---------|
| Opus 4.7 | CLAUDE.md の設計・アーキテクチャ判断・複雑なリファクタリング | 定型の CRUD 実装 | 高 |
| Sonnet 4.6 | 日常的な実装・CLAUDE.md に従ったコーディング・PR 作成 | 大量の単純処理 | 中（メイン） |
| Haiku 4.5 | ドキュメント生成・コメント追加・単純なテンプレート埋め | 複雑な設計判断 | 低 |

### CLAUDE.md の質がモデルのコスパに直結する

CLAUDE.md が充実しているほど、低コストモデルでも意図通りに動く。
- 良い CLAUDE.md → Sonnet や Haiku でもミスが少ない
- CLAUDE.md なし → Opus でも毎回ルールを口頭で説明する必要がある

**コスト最適化の原則:** CLAUDE.md への投資が実装コストを下げる。

### サブエージェントでのモデル選択

| タスク | 推奨モデル | 理由 |
|--------|-----------|------|
| アーキテクチャ設計・CLAUDE.md 作成 | Opus 4.7 | 長期的な整合性の判断が必要 |
| 通常の実装・テスト生成 | Sonnet 4.6 | コスパ最良のメインモデル |
| コメント追加・ドキュメント生成 | Haiku 4.5 | 定型処理でコスト抑制 |
