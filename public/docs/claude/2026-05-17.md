## 🆕 今週の注目トピック

### MCP（Model Context Protocol）とは

MCP は Claude Code に「追加のツール」を提供するためのプロトコル。デフォルトで使えるファイル読み書き・Bash 実行に加えて、自分のサービスやデータベースに直接アクセスするツールを追加できる。

**標準で使えるツール:**
- ファイル操作（Read / Write / Edit）
- シェル実行（Bash）
- Web 検索・フェッチ

**MCP で追加できるもの（例）:**
- Neon / PostgreSQL への直接クエリ
- Stripe のサブスク状況確認
- Slack へのメッセージ送信
- 社内 API の呼び出し

### MCP サーバーの仕組み

MCP サーバーは stdio（標準入出力）または HTTP で Claude Code と通信するプロセス。

```
Claude Code ←→ MCP サーバー ←→ データベース / 外部 API
```

Claude Code の設定ファイル（`~/.claude/settings.json` またはプロジェクトの `.claude/settings.json`）でサーバーを登録する。

```json
{
  "mcpServers": {
    "my-db": {
      "command": "node",
      "args": ["./scripts/mcp-server.js"],
      "env": {
        "DATABASE_URL": "postgresql://..."
      }
    }
  }
}
```

## ⚡ 開発効率を上げる実践 Tips

### 1. 最小構成の MCP サーバーを自作する

`@modelcontextprotocol/sdk` を使うと 50 行以下で動く MCP サーバーを作れる。

```bash
npm install @modelcontextprotocol/sdk tsx
```

```typescript
// scripts/mcp-server.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js'
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js'
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js'

const server = new Server(
  { name: 'my-tools', version: '1.0.0' },
  { capabilities: { tools: {} } }
)

// 利用可能なツール一覧を返す
server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: 'get_user_count',
      description: 'データベースのユーザー数を取得する',
      inputSchema: {
        type: 'object',
        properties: {},
        required: [],
      },
    },
  ],
}))

// ツールを実行する
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === 'get_user_count') {
    const count = await getUserCount()
    return {
      content: [{ type: 'text', text: `ユーザー数: ${count}` }],
    }
  }
  throw new Error(`Unknown tool: ${request.params.name}`)
})

async function main() {
  const transport = new StdioServerTransport()
  await server.connect(transport)
}

main()
```

### 2. データベース接続 MCP サーバー

Neon や PostgreSQL に直接問い合わせられるサーバー。開発中に「今のユーザー数は？」「直近のエラーログは？」を自然言語で聞けるようになる。

```typescript
import { neon } from '@neondatabase/serverless'

const sql = neon(process.env.DATABASE_URL!)

server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params

  switch (name) {
    case 'run_query': {
      const { query } = args as { query: string }
      // 読み取り専用クエリのみ許可
      if (!query.trim().toUpperCase().startsWith('SELECT')) {
        return {
          content: [{ type: 'text', text: 'エラー: SELECT クエリのみ実行できます' }],
        }
      }
      const rows = await sql(query)
      return {
        content: [{ type: 'text', text: JSON.stringify(rows, null, 2) }],
      }
    }

    case 'get_table_schema': {
      const { table } = args as { table: string }
      const schema = await sql`
        SELECT column_name, data_type, is_nullable
        FROM information_schema.columns
        WHERE table_name = ${table}
        ORDER BY ordinal_position
      `
      return {
        content: [{ type: 'text', text: JSON.stringify(schema, null, 2) }],
      }
    }
  }

  throw new Error(`Unknown tool: ${name}`)
})
```

### 3. Stripe MCP サーバー — サブスク状況を即確認

開発中に「このユーザーのサブスクは有効か？」を Claude Code から直接確認できる。

```typescript
import Stripe from 'stripe'

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!)

const tools = [
  {
    name: 'get_subscription',
    description: 'メールアドレスでユーザーのサブスク状況を確認する',
    inputSchema: {
      type: 'object',
      properties: {
        email: { type: 'string', description: 'ユーザーのメールアドレス' },
      },
      required: ['email'],
    },
  },
]

// handler 内
case 'get_subscription': {
  const { email } = args as { email: string }
  const customers = await stripe.customers.list({ email, limit: 1 })
  if (!customers.data.length) {
    return { content: [{ type: 'text', text: '顧客が見つかりません' }] }
  }
  const customer = customers.data[0]
  const subscriptions = await stripe.subscriptions.list({
    customer: customer.id,
    status: 'active',
    limit: 1,
  })
  const sub = subscriptions.data[0]
  if (!sub) {
    return { content: [{ type: 'text', text: 'アクティブなサブスクなし' }] }
  }
  const periodEnd = sub.items.data[0]?.current_period_end
  return {
    content: [{
      type: 'text',
      text: `ステータス: ${sub.status}\n期限: ${new Date(periodEnd * 1000).toLocaleDateString('ja-JP')}`,
    }],
  }
}
```

### 4. `.claude/settings.json` でプロジェクト専用 MCP を管理する

グローバル設定（`~/.claude/settings.json`）より、プロジェクトごとの設定（`.claude/settings.json`）を使うと管理しやすい。

```json
{
  "mcpServers": {
    "db": {
      "command": "npx",
      "args": ["tsx", "scripts/mcp-db.ts"],
      "env": {
        "DATABASE_URL": "${DATABASE_URL}"
      }
    },
    "stripe": {
      "command": "npx",
      "args": ["tsx", "scripts/mcp-stripe.ts"],
      "env": {
        "STRIPE_SECRET_KEY": "${STRIPE_SECRET_KEY}"
      }
    }
  }
}
```

`${DATABASE_URL}` のように書くと、シェルの環境変数を参照できる。`.env` の値が自動で使われる。

### 5. MCP サーバーのデバッグ方法

MCP サーバーは標準出力でやり取りするため、デバッグには `stderr` を使う。`stdout` に出力すると通信が壊れる。

```typescript
// ❌ stdout に出力すると MCP 通信が破壊される
console.log('デバッグ:', data)

// ✅ stderr に出力する
console.error('デバッグ:', data)
process.stderr.write(`デバッグ: ${JSON.stringify(data)}\n`)
```

ログをファイルに書き出す方法も有効：

```typescript
import { appendFileSync } from 'fs'

function debug(msg: string) {
  appendFileSync('/tmp/mcp-debug.log', `${new Date().toISOString()} ${msg}\n`)
}
```

### 6. 既製の MCP サーバーを活用する

自作しなくても、公式・コミュニティ製のサーバーが揃っている。

```bash
# GitHub 操作
npx @modelcontextprotocol/server-github

# ファイルシステム（追加権限付き）
npx @modelcontextprotocol/server-filesystem

# PostgreSQL 直接接続
npx @modelcontextprotocol/server-postgres

# Brave Search API
npx @modelcontextprotocol/server-brave-search
```

設定例（GitHub MCP）：

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}
```

これを入れると「このリポジトリの open issue 一覧を見せて」「PR #42 のコメントを取得して」が Claude Code から直接できる。

### プロジェクト専用 MCP サーバーを 30 分で作る

**ステップ 1: SDK をインストール**

```bash
npm install @modelcontextprotocol/sdk tsx
```

**ステップ 2: サーバーファイルを作成**

```typescript
// scripts/mcp-local.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js'
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js'
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js'
import { neon } from '@neondatabase/serverless'

const sql = neon(process.env.DATABASE_URL!)
const server = new Server(
  { name: 'local-tools', version: '1.0.0' },
  { capabilities: { tools: {} } }
)

server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: 'user_stats',
      description: '登録ユーザー数・有料ユーザー数・本日の新規登録数を返す',
      inputSchema: { type: 'object', properties: {}, required: [] },
    },
  ],
}))

server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === 'user_stats') {
    const [total] = await sql`SELECT COUNT(*) FROM users`
    const [paid] = await sql`
      SELECT COUNT(*) FROM users WHERE subscribed_until > NOW()
    `
    const [today] = await sql`
      SELECT COUNT(*) FROM users WHERE created_at > CURRENT_DATE
    `
    return {
      content: [{
        type: 'text',
        text: `総ユーザー: ${total.count}\n有料: ${paid.count}\n本日新規: ${today.count}`,
      }],
    }
  }
  throw new Error('Unknown tool')
})

const transport = new StdioServerTransport()
await server.connect(transport)
```

**ステップ 3: `.claude/settings.json` に登録**

```json
{
  "mcpServers": {
    "local": {
      "command": "npx",
      "args": ["tsx", "scripts/mcp-local.ts"],
      "env": { "DATABASE_URL": "${DATABASE_URL}" }
    }
  }
}
```

**ステップ 4: Claude Code から使う**

Claude Code を再起動すると `/mcp` でサーバーの状態が確認できる。そのまま「user_stats を実行して」と話しかけるだけで DB の状態を返してくれる。

## 💡 モデル使い分けガイド（週1回更新）

| モデル | 主な用途 | 向かないケース | コスト感 |
|--------|----------|---------------|---------|
| Opus 4.7 | エージェント設計・複雑な推論・セキュリティ監査 | 定型作業・高頻度バッチ | 高 |
| Sonnet 4.6 | API 組み込み・日常コーディング・MCP サーバー開発 | 超単純な変換処理 | 中（メイン） |
| Haiku 4.5 | バッチ処理・大量ドキュメント変換・分類タスク | 複雑な推論が必要なもの | 低 |

### MCP 開発でのモデル選択

| タスク | 推奨モデル | 理由 |
|--------|-----------|------|
| MCP サーバーの設計・ツールスキーマ設計 | Sonnet 4.6 | 型定義と実装の整合が必要 |
| デバッグ・エラー調査 | Sonnet 4.6 | ログ解析と推論のバランス |
| 定型ボイラープレートの生成 | Haiku 4.5 | パターンが決まっているため |
| マルチエージェント MCP 設計 | Opus 4.7 | アーキテクチャ全体の整合が必要 |

### 今週のコスト最適化ポイント

MCP サーバー経由で Claude Code が DB を直接参照できる場合、「データを貼り付けて聞く」より効率的。長いコンテキストを削れるためコスト削減にもなる。

- **DB 接続 MCP**: SQL 結果を貼り付ける代わりにツール呼び出し → 入力トークン削減
- **キャッシュ対象**: MCP ツールの説明文は変わらないのでシステムプロンプトと一緒にキャッシュされる
- **Haiku + MCP**: 定型データ取得 + 簡単な集計は Haiku で十分
