### Claude Agent SDK でカスタムエージェントを作る

Claude Agent SDK は、Claude Code のエージェント機能をプログラムから制御するための SDK。「特定のタスクを繰り返す専用エージェント」を自分で作れる。

個人開発での活用例:
- **コードレビューボット**: PR が作られると自動で Claude がレビューコメントを投稿
- **ドキュメント生成エージェント**: コードが変更されると README や仕様書を自動更新
- **データ分析エージェント**: 毎朝 DB を分析して Slack にサマリーを投稿

```typescript
// Agent SDK を使った基本的なエージェント構成（概念コード）
import Anthropic from '@anthropic-ai/sdk'

const client = new Anthropic()

async function runCodeReviewAgent(prDiff: string) {
  const response = await client.messages.create({
    model: 'claude-sonnet-4-6',
    max_tokens: 4096,
    system: `あなたは厳格なコードレビュアーです。
セキュリティ・パフォーマンス・可読性の3観点でレビューしてください。
問題点は重要度（高・中・低）をつけて列挙してください。`,
    messages: [
      {
        role: 'user',
        content: `以下の差分をレビューしてください:\n\n${prDiff}`,
      },
    ],
  })

  return response.content[0].type === 'text' ? response.content[0].text : ''
}
```

### Managed Agents（管理エージェント）の概念

複数のエージェントを協調させる「マルチエージェント構成」が実用的になっている。

```
オーケストレーター（指揮者）
  ├── リサーチエージェント（情報収集）
  ├── コーディングエージェント（実装）
  └── レビューエージェント（検証）
```

Claude Code の `/subagent` や Agent ツールはこの構成を内部で使っている。自前でも同じパターンを実装できる。

## ⚡ 開発効率を上げる実践Tips

### 1. プロンプトキャッシュでコストを 90% 削減する

Claude API には「プロンプトキャッシュ」がある。同じシステムプロンプトやコンテキストを繰り返し使う場合、2回目以降のリクエストは大幅にコストが下がる。

```typescript
const response = await client.messages.create({
  model: 'claude-sonnet-4-6',
  max_tokens: 1024,
  system: [
    {
      type: 'text',
      text: `あなたはコードレビュアーです。以下のコーディング規約に従って...（長い規約テキスト）`,
      // ↓ これを付けるとキャッシュされる
      cache_control: { type: 'ephemeral' },
    },
  ],
  messages: [{ role: 'user', content: prDiff }],
})
```

**キャッシュが効くのは:**
- システムプロンプトが同じ
- 会話履歴の先頭部分が同じ（ドキュメントを最初に渡すパターン）
- 同じファイルを繰り返し読み込む処理

**目安のコスト削減率:** キャッシュヒット時は入力トークンのコストが約 90% 削減される。

### 2. Extended Thinking（拡張思考）を使う場面

拡張思考は、複雑な判断が必要なときに Claude が「内部で考えてから答える」モード。トークン消費は増えるが、難しい問題の精度が上がる。

```typescript
const response = await client.messages.create({
  model: 'claude-sonnet-4-6',
  max_tokens: 16000,
  thinking: {
    type: 'enabled',
    budget_tokens: 10000, // 思考に使うトークン上限
  },
  messages: [
    {
      role: 'user',
      content: 'この認証フローにセキュリティ上の問題がないか詳しく分析してください',
    },
  ],
})
```

**向いている用途:**
- セキュリティ監査（見落としを減らす）
- 複数ファイルにまたがるバグの根本原因調査
- アーキテクチャの意思決定（トレードオフが多い場合）

**向いていない用途:**
- 定型コードの生成（過剰品質で遅くなるだけ）
- 単純な翻訳・フォーマット変換

### 3. ストリーミングで UX を改善する

Claude の応答が長いとき、ストリーミングを使うと体感速度が大幅に改善する。

```typescript
const stream = await client.messages.stream({
  model: 'claude-sonnet-4-6',
  max_tokens: 4096,
  messages: [{ role: 'user', content: prompt }],
})

// 文字が出てくるたびに処理
for await (const chunk of stream) {
  if (
    chunk.type === 'content_block_delta' &&
    chunk.delta.type === 'text_delta'
  ) {
    process.stdout.write(chunk.delta.text)
  }
}

const finalMessage = await stream.finalMessage()
```

Next.js の API Route からフロントエンドにストリーミングする場合は `ReadableStream` を使う。

### 4. ツール呼び出し（Function Calling）を組み合わせる

Claude に「何かを調べてから答えさせる」ときはツール呼び出しを使う。

```typescript
const tools = [
  {
    name: 'get_file_content',

    input_schema: {
      type: 'object' as const,
      properties: {
        path: { type: 'string', description: 'ファイルパス' },

      required: ['path'],

const response = await client.messages.create({
  model: 'claude-sonnet-4-6',

// Claude がツールを呼び出したかチェック
if (response.stop_reason === 'tool_use') {
  const toolUse = response.content.find(b => b.type === 'tool_use')
  // ツールを実行して結果を返す処理...
}
```

### 5. エラーハンドリングとリトライを正しく実装する

Claude API はレートリミットや一時的なエラーが発生することがある。指数バックオフでリトライする。

```typescript
import Anthropic from '@anthropic-ai/sdk'

const client = new Anthropic()

async function callWithRetry(
  prompt: string,
  maxRetries = 3
): Promise<string> {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      const response = await client.messages.create({
        model: 'claude-sonnet-4-6',
        max_tokens: 1024,
        messages: [{ role: 'user', content: prompt }],
      })
      return response.content[0].type === 'text'
        ? response.content[0].text
        : ''
    } catch (error) {
      if (error instanceof Anthropic.RateLimitError) {
        // レートリミット: 指数バックオフ
        const wait = Math.pow(2, attempt) * 1000
        console.log(`Rate limited. Waiting ${wait}ms...`)
        await new Promise(r => setTimeout(r, wait))
      } else if (error instanceof Anthropic.APIError && error.status >= 500) {
        // サーバーエラー: リトライ
        await new Promise(r => setTimeout(r, 1000 * (attempt + 1)))
      } else {
        // それ以外: リトライしない
        throw error
      }
    }
  }
  throw new Error('Max retries exceeded')
}
```

### 6. バッチ処理で大量リクエストのコストを下げる

急ぎでない処理（日次バッチ、データ変換など）は Message Batches API を使うとコストが約 50% 削減される。

```typescript
const batch = await client.messages.batches.create({
  requests: documents.map((doc, i) => ({
    custom_id: `doc-${i}`,
    params: {
      model: 'claude-haiku-4-5-20251001',
      max_tokens: 1024,
      messages: [
        { role: 'user', content: `この文書を要約してください:\n${doc}` },
      ],
    },
  })),
})

// バッチ完了を待つ
let result = await client.messages.batches.retrieve(batch.id)
while (result.processing_status === 'in_progress') {
  await new Promise(r => setTimeout(r, 5000))
  result = await client.messages.batches.retrieve(batch.id)
}
```

### Next.js アプリに Claude を組み込む最小構成

Next.js の API Route から Claude を呼び出す最もシンプルな構成。

```typescript
// app/api/ai/route.ts
import Anthropic from '@anthropic-ai/sdk'
import { NextRequest } from 'next/server'

const client = new Anthropic()

export async function POST(req: NextRequest) {
  const { prompt } = await req.json()

  // ストリーミングで返す
  const encoder = new TextEncoder()
  const stream = new ReadableStream({
    async start(controller) {
      const messageStream = client.messages.stream({
        model: 'claude-sonnet-4-6',
        max_tokens: 2048,
        messages: [{ role: 'user', content: prompt }],
      })

      for await (const chunk of messageStream) {
        if (
          chunk.type === 'content_block_delta' &&
          chunk.delta.type === 'text_delta'
        ) {
          controller.enqueue(encoder.encode(chunk.delta.text))
        }
      }
      controller.close()
    },
  })

  return new Response(stream, {
    headers: { 'Content-Type': 'text/plain; charset=utf-8' },
  })
}
```

```typescript
// フロントエンド側
async function askClaude(prompt: string) {
  const res = await fetch('/api/ai', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ prompt }),
  })

  const reader = res.body!.getReader()
  const decoder = new TextDecoder()
  let text = ''

  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    text += decoder.decode(value)
    setOutput(text) // React state を更新してリアルタイム表示
  }
}
```

### 自前の Claude Code ラッパーを作る

繰り返すタスクは CLI ラッパーにしてしまうと便利。

```bash
#!/bin/bash
# scripts/review.sh — PR の差分をレビューさせる

DIFF=$(git diff main...HEAD)

echo "$DIFF" | claude --print "
このコードの差分をレビューしてください。
以下の観点で問題点があれば指摘してください:
1. セキュリティ上の懸念
2. N+1 クエリなどのパフォーマンス問題
3. エラーハンドリングの漏れ
4. テストが必要だが書かれていない箇所

問題がなければ '問題なし' とだけ返してください。
"
```

## 💡 モデル使い分けガイド（週1回更新）

| モデル | 主な用途 | 向かないケース | コスト感 |
|--------|----------|---------------|---------|
| Opus 4.7 | エージェント設計・複雑な推論・セキュリティ監査 | 定型作業・高頻度バッチ | 高 |
| Sonnet 4.6 | API 組み込み・日常コーディング・ストリーミング応答 | 超単純な変換処理 | 中（メイン） |
| Haiku 4.5 | バッチ処理・大量ドキュメント変換・分類タスク | 複雑な推論が必要なもの | 低 |

### SDK を使う際のモデル選択指針

```typescript
// ユーザーが待つインタラクティブな処理 → Sonnet（速度と品質のバランス）
const interactive = 'claude-sonnet-4-6'

// 夜間バッチや非同期処理 → Haiku（コスト優先）
const batch = 'claude-haiku-4-5-20251001'

// 週次の設計レビュー・監査 → Opus（品質優先）
const audit = 'claude-opus-4-7'
```

### 今週のコスト最適化ポイント

プロンプトキャッシュとバッチ API の組み合わせで、同じ品質を維持しながらコストを大幅削減できる。

- **キャッシュ**: システムプロンプトが長い処理（コードレビュー・ドキュメント生成）→ 最大 90% 削減
- **バッチ**: 急がない大量処理（日次サマリー・データ分類）→ 約 50% 削減
- **Haiku**: 分類・抽出など単純タスク → Sonnet 比で約 75% 削減
